# Java movement target

The target is Minecraft Java Edition 1.21.1 on ordinary solid ground, without
status effects. One block maps to one Havok metre; Skyrim's world scale supplies
the conversion to its editor units. Skyrim still resolves its own collisions.

The implementation is an independent C++ model. Mojang's locally downloaded
1.21.1 client and official mappings were inspected to verify creative-flight
input, the seven-tick double-tap window, and the flight/FOV multipliers. Neither
the client nor its bytecode is included in this repository. The local downloads
were checked against Mojang's published SHA-1 values:

- Client: `30c73b1c5da787909b2f73340419fdf13b9def88`
- Mappings: `2244b6f072256667bcd9a73df124d6c58de77992`
- Metadata source: [Mojang version manifest](https://piston-meta.mojang.com/mc/game/version_manifest_v2.json).

## Parameters and ordering

The simulation runs at 20 ticks/second. Quantities in this table use blocks and
ticks; the engine adapter receives metres/second.

| Quantity | Value |
| --- | --- |
| Jump impulse | 0.42 blocks/tick |
| Gravity, applied after movement | 0.08 blocks/tick² |
| Vertical retained velocity | 0.98 per tick |
| Normal ground retained horizontal velocity | 0.6 × 0.91 = 0.546 |
| Air retained horizontal velocity | 0.91 |
| Ground/air input acceleration | 0.1 / 0.02 blocks/tick² |
| Forward sprint multiplier | 1.3 |
| Sneaking input multiplier | 0.3 |
| Input damping before normalization | 0.98 |
| Sprint-jump forward impulse | 0.2 blocks/tick |
| Held-jump cooldown | 10 ticks, reset on release |
| Creative horizontal acceleration | 0.05; Ctrl doubles it |
| Creative vertical acceleration | ±0.15 blocks/tick² |
| Creative retained vertical velocity | 0.6 per tick |
| Flight FOV multiplier | 1.1; Ctrl adds the 1.15 sprint multiplier |

Move first, then apply gravity and drag for the next tick. A jump reaches about
1.2522 blocks above its takeoff position in this model. Long falls approach
78.4 blocks/second. On normal ground, forward walking approaches 4.3172 and
sprinting 5.6123 blocks/second. Java 1.21.1's 0.98 input scaling occurs before
diagonal normalization, so its small diagonal speed difference is preserved.

Creative horizontal flight approaches 10.8889 blocks/second, or 21.7778 with
Ctrl. Ascent/descent approaches 7.5 blocks/second independently of horizontal
movement. Sneak slows ground movement, but does not slow horizontal creative
flight when used to descend; the actual Java LocalPlayer's crouching check
excludes flying. Releasing a key coasts using the corresponding drag. Landing
ends creative flight after takeoff. F6 is an additional shortcut to the same
flight toggle as double Space, with no separate arming step.

The adapter integrates portions of each 50 ms tick when render frames do not
align with ticks. It supplies the interval's mean velocity to Havok, preserving
the intended displacement instead of stretching the last tick over the frame.

Gliding uses the Java gravity/lift, dive-transfer, pitch-up conversion, steering,
and axis-drag rules. Ctrl uses the Java firework acceleration rule while held;
using magicka as its resource is this mod's Skyrim-specific adaptation. Creative
flight uses neither stamina nor magicka. Its FOV change eases halfway toward the
target per 50 ms and restores the existing world FOV after flight, F10, load, or
a scripted control handoff. It does not alter the saved FOV settings.

## Independent regression data

`tests/fixtures/minecraft-java-1.21.1.csv` contains 900 ticks generated by
[Prismarine Physics, commit 5a46cc9](https://github.com/PrismarineJS/prismarine-physics/tree/5a46cc9d0222543d1693063d0726b8d3096255f2).
That project's MIT-licensed implementation runs separately from this C++ model.
The tests compare movement against those numeric outputs, including acceleration,
release/coasting, held jumping, freefall, steering, creative flight, and gliding.
The fixtures exclude simultaneous creative descent and horizontal movement:
that reference currently applies ground sneak scaling in flight, unlike the
verified Java client.

To regenerate, install the reference's dependencies plus `prismarine-block`,
then run `node tools/generate-physics-reference.cjs /absolute/reference/package`.
Ordinary tests use the checked-in CSV and do not need Node, network access, or
Minecraft. Additional tests check displacement at 15/30/60/144 FPS, FOV easing,
double-tap pairing, and the cutscene restrictions. See [live validation](VALIDATION.md)
for measurements in Skyrim; reference agreement alone does not prove the game
adapter or collision behaviour.

## Engine differences

Skyrim retains its capsule, slopes, stairs, terrain, furniture, and water handling.
Its surfaces currently all use normal-block friction; ice, slime, ladders, swimming,
Minecraft's ledge-safe crouching, status effects, and fall-damage rules have not
been ported. Scripted restrictions deliberately use Skyrim's movement until the
game releases control. The model is intended to reproduce Java movement closely
within those limits, rather than claim complete engine parity.
